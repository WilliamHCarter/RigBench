# v0.3.2 — adversarial review of the live loop

An adversarial pass over `d2866fe` returned "request changes before real
campaign". The architecture was not the problem — the persistent worktree,
endogenous tail, hidden-oracle isolation, diagnostic lane and discrimination gate
all stood. Everything found was in timing, stopping semantics, live-record
population, and campaign setup, and most of it escaped the mock acceptance suite
because no real inference had exercised the loop.

All findings accepted. Nothing here changes the interaction model.

## The one that would have cost us a result

**Scope-red could terminate a repairable story.** `ScoreLiveTurn` computed

```go
DiscriminatingGreen = visible.OK() && discriminationGate == pass
```

and `RunLive` stopped on it. But story success also requires `scope`. So a turn
that implemented everything correctly *and* touched one out-of-scope file —
build green, visible green, discrimination green, scope red — ended the loop.
The host had already computed the feedback:

```
HOST CHECK: scope violation. ...
Those files are not yours to change; revert them.
```

and then never sent it. The story was recorded as a failure for a defect the
loop exists to let the model repair.

Fixed with a separate stop predicate. `DiscriminatingGreen` stays as the
milestone — it is a claim about the code, not about which files were touched —
and `ReadyForFinal` adds build and scope. Only `ReadyForFinal` stops the loop.

Pinned by a new acceptance variant, `live-scope-then-repair`, which asserts turn
0 has scope **fail** and discrimination **pass**, so the case cannot silently
stop being reproduced. Under the old code it stopped at turn 0 as a failure;
now it converges at turn 1.

## The clock

Three separate defects, all of which broke the identity
`total == model + tool`.

1. **The final hidden evaluation was never timed** and never added to
   `tool_wall_ms`, while `time_to_hidden_green_ms` was measured *after* it ran.
   The result was `time_to_hidden_green > total_wall` — not a rounding
   difference but a broken invariant.
2. **The diagnostic lane's leaked hidden run and placeholder restore** were
   outside the clock as well.
3. **Milestones were stamped from raw elapsed time** while the total is model
   plus tool, so the two were measuring different clocks and the gap grew with
   harness overhead.

Now: the final evaluation is timed into `final_hidden_wall_ms` and folded into
`tool_wall_ms`; the diagnostic leak into `diagnostic_leak_wall_ms`, likewise;
and every milestone is stamped from the accounted clock. Raw elapsed and the
difference are recorded as `elapsed_wall_ms` and `harness_overhead_ms`, so the
overhead is a visible number rather than either invisible or silently folded in.

The acceptance suite now asserts the identity on **every** story, along with
`final_hidden_wall_ms > 0` and `time_to_hidden_green <= total_wall`.

## `max_wall_seconds` was not a deadline

It was checked only before starting a turn. A story with ten seconds left could
begin a request carrying its own 900-second client timeout and then run build
and test commands carrying theirs — overrunning a declared 3600-second budget by
most of an hour. Exactly the class of mismatch that bit the 32K one-shot run.

Now a `context.WithTimeout` cancels the model request and every tool command in
the loop.

**The semantics decision, made explicitly:** the final hidden evaluation is
*outside* the agent budget. It is the benchmark grading the result, not the
agent working, and a story that used all its time must still be graded — or "ran
out of time" and "was never evaluated" become the same record. The code, the
comment and the lane documentation now agree.

A cancelled request is recorded as a `wall_budget` gate failure, not a transport
failure: the budget doing its job and the transport failing must not aggregate.

The probe that proves it — a mock deliberately slower than the budget — **found
a nil-pointer crash** on that path, because the cancellation branch appended a
record with no `Quality`. The claimed hard deadline had never been exercised.

```
budget 3s, stopped after 7s with "wall-clock budget exhausted"
```

## The next objective contradicted the host

When a diff failed to apply, the model was told:

```
HOST: your diff did not apply. The working tree is UNCHANGED
```

and then, in the same prompt:

```
The host applied your diff and ran the build. Its exact output is above.
```

Contradictory state information, which a scripted mock never notices and a real
model will act on. The objective is now state-neutral: the host result is
authoritative *including whether anything was applied*.

The contract also promised "exact output" while v0.3 deliberately sanitizes and
truncates it. Both the contract and the objective now say what is actually sent:
the compiler's own output, sanitized of machine-specific paths, truncated where
marked.

## Live records were partly fiction

`liveRecord` never populated `appended_bytes` or `turn_count`, so every live row
reported zero prompt growth — while the report printed those fields as
prompt-growth telemetry. And `thermal` was copied from the run's declared class
onto every turn, labelling resident-server turns as cold.

All three fixed and asserted for every story in the acceptance suite.

## Repair turns are not independent trials

Every intermediate turn was `Scored: true` with `Passed` never set, so a green
three-turn story appeared in the generic quality table as one pass and two
failures, with wall-clock eligibility "partial" — contradicting the story
verdict directly above it.

Intermediate turns are now `Scored: false`; their gates stay on the `StoryTurn`
where they are diagnosis. Exactly one record per story carries the verdict, and
the acceptance suite asserts exactly one.

A green two-turn story now reports `1 pass, 0 fail` instead of `1 pass, 1 fail`.

## The output cap was not the cap

`max_tool_output_bytes` was applied per command *and then again* at double the
ceiling in `trimFeedback`, so a 16 KiB lane could send 32 KiB. Separately,
`TruncateMiddle` kept `n` bytes and then appended its elision marker on top.

Tool-result size drives the next turn's prompt size, prefill work, cache shape
and wall clock, so a cap that is not the configured cap is a measurement error.
Now one cap over the whole feedback block, marker inside the budget, with the
scope note placed before truncation so it cannot be elided out of the middle of
a long build log.

## Campaign setup

**Warmup primed the wrong workload.** Every `stepWarmup` ran the one-shot path
regardless of `-lane`, so the documented live campaign primed Hipfire with a
different contract and objective than it measured. `-warmup` is now **refused**
on a live lane, with the reasoning in the error: priming with the one-shot
prompt measures a different workload, and priming with the live prompt would
fill the cache with the story about to be measured. Residency comes from the
preparation hook.

**`-repeats 3` shared prompt-cache state.** Repetitions replay a byte-identical
turn 0 against a server whose cache the previous repetition filled, so a
three-repeat median can become one story plus two cached replays. Now refused
without `-before-engine`, and re-prepared between repetitions when there is one.
The runbook says to start with one repetition and read the trajectory anyway.

**The campaign configs were stale.** They were no-think at 12,288 tokens — the
profile we already closed. Two new configs, `ar-medium-live` and
`dflash2-f16-medium-live`, at medium reasoning with per-turn ceilings from the
lane. The no-think configs are unchanged so the one-shot experiment stays
reproducible.

## Smaller items

- `leak_hidden_after_turn` is validated `< max_turns`. A lane that calls itself
  diagnostic and configures an unreachable leak turn is worse than one that does
  not claim to.
- `restoreHiddenPlaceholder` removes the directory wholesale instead of skipping
  subdirectories, which would have left oracle content where the next turn's
  build compiles it.
- `Stage`'s comment claimed it injects the hidden suite; it deliberately does
  not.
- `Story.StopReason` documented an `apply-failed` reason that does not exist —
  correctly, since an apply failure is repairable. Comment corrected.

## Still not fixed, and deliberately

- **No real inference.** Every finding above escaped a mock suite; the next ones
  will too. The runbook's first live step is now one story per engine, read by
  hand, before any statistics.
- **`identity_probe.require` is still empty** on the rig configs, pending a real
  `/health` response.
- **`verify-fixture` has still never run on the rig**, and the Zig toolchain
  question from [v0.2.3](v0.2.3.md) is still open.
- **Harness overhead is excluded from `total_wall_ms`** — now recorded rather
  than hidden, but still not part of the north-star number.
