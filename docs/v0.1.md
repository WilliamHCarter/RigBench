# v0.1 — single-call runner + cold builder fixture

**Goal.** Prove the end-to-end benchmark skeleton with one deterministic builder
request, and make it possible to answer: *on the same bounded coding task and
objective hidden tests, how much faster is this inference configuration, and did
it still produce a valid patch?*

## The slice and its exact contract

One builder request per engine config, against a frozen fixture, scored by
objective gates. No multi-turn replay, no reviewer fan-out, no live tool loop,
no context-length matrix, no engine tuning — those are v0.2 through v0.7 and
nothing here reaches into them.

## Deliverables

| Deliverable | Where |
|---|---|
| OpenAI-compatible streaming client and request JSONL writer | `internal/client`, `internal/metrics` |
| `zig-playback-v1` repo + Story + visible/hidden tests | `fixtures/zig-playback-v1` |
| Deterministic prompt serializer + SHA/token manifest | `internal/prompt` |
| AR and DFlash engine configs | `configs/engines` |
| Patch extraction/apply + build/test/scope scoring | `internal/executor`, `internal/scoring` |
| Summary comparing correctness + wall time | `internal/report` |
| Deterministic mock endpoint (added, not in the original slice list) | `internal/mock` |

The mock was added because there is no rig reachable from this workstation. It
makes the acceptance gate runnable and CI-able anywhere, and every config that
points at it says in its own description that its timings are a fixture rather
than a measurement.

## Acceptance gate

| Criterion | Result |
|---|---|
| One command runs AR and DFlash against the same frozen task | `agentbench smoke` runs both mock configs; the runner refuses if their prompt hashes differ |
| Both produce complete request records and artifacts | `request.jsonl`, `run.json`, `summary.md`, `summary.csv`, plus prompt, manifest, output, patch, applied diff and every rung's log |
| Hidden controls fail on planted mutants | 12/12 controls behave as declared; 3 pass the visible suite and are caught only by the hidden suite |
| No benchmark code is Hipfire-specific except optional telemetry adapters | The only Hipfire mention outside configs is `client.Hipfire`, behind the `Adapter` interface; the default adapter extracts nothing |

## The fixture

`zig-playback-v1` is a synthetic Zig repository derived from the *shape* of an
E7-S2 playback seam, not a copy of any production tree. The builder task adds
`FrameRange` and `Tone` as cold state, generalizes the cursor to a half-open
range, and must leave the 72-byte `Hot` record and the frozen Player golden
byte-identical.

Canonical contracts:

| Area | Contract |
|---|---|
| `FrameRange` | Half-open `[start,end)`; `start < end`; `end <= frames`; `full(frames)`; invalid ranges refused by name |
| `Tone` | Cold/setup state only; gain plus inherit/bypass/coefficient filter state; default preserves prior behaviour |
| `Hot` | Exactly 72 bytes, `extern`, unchanged field offsets and field *count* |
| `Cursor` | Forward never reads `end`; reverse never reads below `start`; legality checked before state mutation |
| DSP order | reader × envelope × voice gain → optional one-pole → declick; coefficient prepared outside the frame loop |
| Robustness | Non-finite and out-of-domain coefficients, gains and ranges pinned; no pointer retained by a voice |
| Scope | Nine owned files; `build.zig`, `src/core/**`, `products/**` and `hidden/**` are forbidden |

### Hidden suite

45 tests in three files, reached from `hidden/root.zig` and injected into the
worktree only *after* the candidate's own build and visible rungs have run:

- `layout_test.zig` — reflection over `Hot`'s frozen field set, `extern` layout,
  recursive no-pointer check on `Cold`, `Filter`'s exact three cases.
- `invariants_test.zig` — behavioural, over a sample whose value at index *i* is
  exactly *i*, so a rendered frame **is** the index that was read and read-position
  claims are observed in the output rather than asserted about the implementation.
- `structural_test.zig` — reads the engine's own source bytes and isolates the
  frame-loop body. The matcher is driven over probe sources first: one that must
  trip it, one that must not, and one it must report as unparseable. A matcher
  broken into never matching therefore reports as a broken matcher, not as a
  clean tree.

### Anti-vacuity controls

| Mutant | Lens | Build | Visible | Hidden |
|---|---|---|---|---|
| `m01-range-end-inclusive` | correctness | ok | fail | fail |
| `m02-mutate-before-legality` | correctness/adversarial | ok | fail | fail |
| **`m03-tone-in-hot`** | consistency/system-design | ok | **pass** | fail |
| **`m04-coefficient-inside-frame-loop`** | performance | ok | **pass** | fail |
| `m05-reverse-below-start` | adversarial | ok | fail | fail |
| `m06-permissive-coefficient` | completeness/correctness | ok | fail | fail |
| `m07-default-path-moves-player-bytes` | consistency | ok | fail | fail |
| `m08-invalid-range-clamped` | correctness | ok | fail | fail |
| `m09-bypass-inherits` | correctness | ok | fail | fail |
| `m10-explicit-coefficient-ignored` | correctness | ok | fail | fail |
| **`m11-cold-retains-pointer`** | system-design | ok | **pass** | fail |
| `control-syntax-error` | control | fail | fail | fail |

The three bold rows are the argument for the hidden suite existing. `m03` and
`m11` pass the visible suite because the mutation also edits the candidate's own
tests — which is exactly what a builder who grew `Hot` or retained a pointer
would have to do. `m04` produces **bit-identical audio**: no behavioural test can
see it, and only the structural control does.

`control-syntax-error` is not a defect model. It is the control that proves a red
rung is reachable at all, and that a build failure is not silently scored as a
pass — the failure mode that has actually occurred in the source material this
fixture is modelled on, where parallel `zig test` runs collided in a shared cache
and a deliberately-injected syntax error still reported "pass". Every mutant here
gets its own staged worktree and its own cache.

### The gates are individually reachable

The acceptance matrix drives six canned candidates through the pipeline and
requires each to fail at a *named* gate. A benchmark whose scope gate has never
gone red is a benchmark with an untested scope gate.

| Variant | Passed | Gate that caught it |
|---|---|---|
| `reference` | yes | — |
| `visible-green-hidden-red` | no | `hidden_tests` |
| `broken` | no | `visible_tests`, `hidden_tests` |
| `scope-violation` | no | `scope` |
| `unapplyable` | no | `patch_applies` |
| `no-diff` | no | `patch_extracted` |

This satisfies the §8.2 stop condition: v0.1 can distinguish a planted broken
patch from a correct one.

## Bugs found and fixed while building this slice

Recorded because knowing what broke is worth as much as knowing what works.

1. **The order-of-operations hidden test was vacuous.** It claimed to pin
   "reader × envelope × gain, then filter", but with a *constant* gain a one-pole
   is linear and the two orders produce identical bytes — the test could not
   fail. Replaced with a ramped envelope, where the orders genuinely differ
   (`1.0, 2.375, 4.1875, 5.59375` versus `1.0, 2.625, 4.75, 5.875`).
2. **`m03` was misreported as a build failure.** The mutant verdict looked at the
   hidden rung's output for compile errors, so a hidden suite refusing to compile
   against a mutated tree read as "the candidate's build failed". Corrected to
   look only at the candidate's own tree.
3. **The hidden layout check failed with a comptime bounds error** rather than a
   readable message. Now compared over the overlap first, so a field-count change
   reports as a field-count change and names the added fields.
4. **A `diff`-tagged fence was accepted without checking its contents**, splitting
   one defect across `patch_extracted` and `patch_applies`. The tag is a claim;
   the contents are the fact.
5. **`git apply` was given a repo-relative path** while running with the worktree
   as its working directory, so every patch failed to apply.
6. **The mock's timing profile never switched.** Both engine configs shared a
   model alias, so the DFlash row silently used the AR shape. Profiles are now
   selected by an engine-declared request header, which keeps endpoint-specific
   knowledge out of the runner.
7. **The volatile-token guard fired on the smoke run's own run id.** The guard was
   right: a run id of `reference` collides with the fixture's prose. Run ids are
   now timestamp-shaped and the output directory name is a separate field.

## Unmeasured, stated rather than covered

- **Reasoning quality.** The score is the diff, the gates and the wall clock.
  Prose is not read, deliberately, so the score cannot depend on writing style.
- **A per-frame computation moved into a helper.** The structural control inspects
  only the first `while` body inside `renderBlock`. Work hidden behind a call from
  that loop is invisible to it and stays invisible.
- **Real-time safety as a timing bound.** The doctrine rule is checked as the
  absence of named constructs, not as measured latency.
- **The token count is not exact.** `approx-runs-v1` is a heuristic, is recorded
  as such in every row, and reports `token_count_is_exact: false`. No context
  variant may be labelled by size until v0.5 wires the target tokenizer.
- **The Hipfire telemetry key names are provisional.** They have not been
  confirmed against a running Hipfire server from this workstation. They are read
  defensively, so a wrong guess yields `null` rather than a fabricated number —
  but they need confirming on the rig before any DFlash telemetry column is
  believed.
- **No real inference has been run.** Every timing in this slice came from the
  in-repo mock.
- **GPU, driver and ROCm identity are collected only on Linux.** On this macOS
  workstation those fields are empty, and `run.json` records which probes were
  attempted so an empty field is distinguishable from one nobody looked for.
