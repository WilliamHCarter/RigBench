# v0.2.2 — review fixes: run schedule topology

A second review pass found one remaining P0 that would have invalidated every
`-repeats 3` run, plus a P1 in the same loop and a one-line script correction.

## P0 — repetitions switched back to the wrong engine

The runner looped repetition-outer, engine-inner, and prepared each engine only
on the first repetition:

```
rep 0:  prepare AR      measure "AR"      -> AR       correct
        prepare DFlash  measure "DFlash"  -> DFlash   correct
rep 1:                  measure "AR"      -> DFlash   WRONG
                        measure "DFlash"  -> DFlash   correct
rep 2:                  measure "AR"      -> DFlash   WRONG
                        measure "DFlash"  -> DFlash   correct
```

After repetition 0, DFlash is the daemon left running and nothing prepares AR
again. Two thirds of the steady-state AR samples would have been DFlash samples
wearing an AR label — and they would have aggregated into the AR cell's median
without anything looking wrong.

### Fix

Engine outer, repetition inner, preparation once per engine, warmup once per
engine:

```
prepare AR       warm AR once      AR rep 1  AR rep 2  AR rep 3
prepare DFlash   warm DFlash once  DFlash rep 1  DFlash rep 2  DFlash rep 3
```

The schedule is now a pure function in `cmd/agentbench/schedule.go` rather than
nested loops, so the topology is a thing that can be tested rather than a thing
that has to be read carefully. Its invariant:

> every measurement is preceded by a preparation of its own engine, with no
> other engine's preparation in between

is checked by `checkSchedule`, which the runner calls before the first request is
sent, and which a test drives over the *old, broken* schedule to prove the check
is not vacuous.

Verified end to end against the mock with the preparation hook attached:

```
-> preparing mock-ar
   warmup for mock-ar (discarded)
-> mock-ar rep 1/3
-> mock-ar rep 2/3
-> mock-ar rep 3/3
-> preparing mock-dflash2
   warmup for mock-dflash2 (discarded)
-> mock-dflash2 rep 1/3
-> mock-dflash2 rep 2/3
-> mock-dflash2 rep 3/3
```

### Repeated *cold* measurements

Moving preparation out of the repetition loop exposed a second case the old code
never handled either: a repeated cold measurement is only cold if something
returns the server to a cold state between repeats.

- `-thermal cold` with `-repeats > 1` now prepares before **every** repetition
  and never warms.
- `-thermal cold -repeats > 1` with no `-before-engine` is **refused**, because
  repeats 2..N would be warm rows wearing a cold label:

```
-thermal cold with -repeats 3 needs a way to return the server to a cold state
between repetitions. Pass -before-engine, or use -repeats 1, or declare
-thermal steady with -warmup 1
```

Repeated preparation writes distinct artifacts (`<engine>.rep2.prepare.log`)
rather than overwriting its own evidence.

## P1 — `-warmup 1 -repeats 3` meant three warmups

The warmup loop was inside the repetition loop, so the runbook's "one discarded
warmup, three repetitions" actually produced warmup/measure/warmup/measure/
warmup/measure.

Not cosmetic. The warmup sends the same benchmark prompt, so priming immediately
before every measurement measures *an identical request replayed against a fully
populated prefix cache* rather than a resident engine with hot execution — a
different and much rosier thing, and one that would have flattered the
cache-friendly layout in particular.

Warmup is now once per engine, after preparation and before the first
measurement. `run.json`'s `warmup_policy` states this explicitly, including
whether engines were interleaved, so the schedule that produced a set of rows is
recorded rather than remembered.

Records also gained a `repetition` field, so a cell's dispersion can be traced to
individual repeats instead of only appearing as a min..max.

## Tiny — `hipfire config ... show` → `list`

`scripts/prepare-hipfire.sh` ended with `hipfire config "$MODEL" show`. The
noninteractive command is `list`. The script tolerated the failure, so this cost
preparation evidence rather than breaking a run.
