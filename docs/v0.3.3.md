# v0.3.3 — make the Hipfire adapter describe the actual machine

The live-loop core was approved; the remaining findings were rig integration.
All nine items in the ticket, in the order they block a campaign.

## Three hard blockers, all in the path from `run` to inference

### 1. The medium configs could not be prepared

The configs are named `ar-medium` and `dflash2-f16-medium`; the hook accepted
only `ar` and `dflash2-f16` and `FATAL`s on anything else. Step 3b aborted before
a single request.

Fixed the way the review preferred long-term rather than with an alias, because
display identity and server preparation really are different things: `ar-medium`
and `ar-xhigh` are two rows in a report and one server setup. Engine configs
gained `prepare_profile`, defaulting to `name`:

```json
"name": "ar-medium",
"prepare_profile": "ar"
```

The runner hands the hook the profile. The hook *also* accepts the display names
defensively, since an operator running it by hand reaches for the name they saw
in the report.

### 2. The health alias was not wired into the campaign

The hook supported `AGENTBENCH_HEALTH_MODEL` but defaulted it to the serve alias,
and nothing in the runbook set it. On this rig serving `qwen3.8:27b-fast` yields
`/health.model = qwen3.8:27b-mq4-xt`, so the default recreated the five-minute
false readiness timeout we already debugged.

The default is now the value this rig actually reports, overridable for any
other, and the rig configs assert it:

```json
"require": { "model": "qwen3.8:27b-mq4-xt" }
```

Hipfire's health payload does not expose speculation state, so this attests the
resolved target only — the arm is attested by the preparation log's config dump.
Both facts are now written down in the runbook instead of living in a terminal
session.

### 3. `context_tokens` mapped to a key that does not exist

Both medium configs requested `context_tokens: 32768`, which the hook translated
to `hipfire config set context_length` — not a key on this build. Prep would have
aborted.

Two changes. The axis now maps to **`max_seq`**, and `context_tokens` is
**removed from the baseline configs entirely**: the baseline is not a context
experiment, and pinning an arbitrary capacity adds a variable to an
AR-vs-DFlash comparison nobody asked a question about.

## The lifecycle bug, folded in from `/tmp`

`hipfire stop` has been observed to kill the foreground serve process while
leaving `~/.hipfire/bin/daemon` alive, so the next launch fails with "daemon
already running". The workaround lived in `/tmp/rigbench-prep-clean.sh`.

It is now `stop_hipfire` in the repo hook: reap only that exact managed binary,
wait, escalate to SIGKILL, clear stale pidfiles, and verify. It **fails closed**
if the port is still held — and deliberately does not kill a listener it did not
start, because that is somebody else's process.

This matters more than it did before v0.3.2: the live-lane repeat protocol now
relies on re-preparation between stories to keep prompt caches from contaminating
each other, so an intermittently-failing restart silently breaks a guarantee the
runner is enforcing.

## The clock, once more

`TimeToHiddenGreenMS` was stamped **before** the hidden suite's own duration was
added to `ToolWallMS`. Since a story cannot be known green until that suite has
finished, the milestone understated itself by exactly that duration.

The fix is ordering: close the clock, then stamp the verdict. And the acceptance
assertion is tightened from an upper bound to **equality** — the old check passed
precisely because the value was too small.

```go
story.FinalHiddenWallMS = ...
story.ToolWallMS += story.FinalHiddenWallMS
story.TotalWallMS = story.ModelWallMS + story.ToolWallMS
story.HiddenGreen = ...
if story.HiddenGreen {
    story.TimeToHiddenGreenMS = metrics.Ptr(story.TotalWallMS)
}
```

The last three fail closed rather than guessing:

```
FATAL: AGENTBENCH_KNOB_SPECULATIVE_BLOCK is set, but this hook has no VERIFIED
Hipfire key for it. Identify the real control in CONFIG.md and map it here.
Do not guess: a guessed key records a setting the server never had.
```

PM4 is the interesting one — it is a launch-time env var on the retained gfx1201
verification path, not a per-model config key, so it is exported for the serve
invocation rather than passed to `config set`. A non-boolean value is refused.

### `--check-knobs`

New pre-flight mode. No Hipfire toolchain, no server, one second:

```bash
./scripts/prepare-hipfire.sh ar --check-knobs
```

It resolves every axis, prints the key each maps to, and exits non-zero on
anything refused or unmapped. Building it surfaced a hole: the first version
returned before the engine-name dispatch, so a typo'd name got a green light —
the opposite of what a pre-flight check is for. It now validates the name too.

## Provenance populated

The paths and digests were already known and were sitting in shell notes:

```json
"target_file":   "/home/willy/.hipfire/models/qwen3.8-27b.mq4r",
"target_sha256": "6107298079...762e",
"draft_file":    "/home/willy/.hipfire/models/qwen3.8-27b-dflash2-f16.hfq",
"draft_sha256":  "d466f5b611...112c"
```

on all four rig configs, so the first live dataset starts with provenance rather
than having hashes attached retroactively. Where the file is readable the harness
recomputes the digest and the declared value is only a fallback.

## The telemetry parser was fictional about our own logs

It parsed `key=value` and documented a line shape the pinned server does not
print. The real form is:

```
[req 7f3a] drafter=dflash tau=4.86 tok/s=32.9 decode (32768 tok, 5593 windows)
```

so `drafter`, `tau` and `tok/s` were read and `windows` stayed null — against the
very server the parser was written for. A second pattern now reads the
parenthetical.

Accepted and rejected tokens are deliberately **not** derived from it. Token
count over window count is an average window size, not an acceptance figure, and
a guessed metric is worse than a null one. Pinned by
`TestParentheticalDoesNotInventAcceptedOrRejected`.

## Runbook

Now opens with **what this rig is** — serve alias, resolved health identity,
artifact paths and digests, endpoint — so nobody re-derives it from a terminal.
Step 0 leads with `--check-knobs`. The stale claim that `/health.model` should be
`qwen3.8:27b-fast` is corrected. The "every config here is no-think" paragraph
is replaced: steps 2–3 are no-think and measure the floor, step 3b onward is
medium, and their rows never aggregate because `thinking` is part of every record.

Step 3b now says explicitly: **run AR first, read it, then run DFlash.** Not both
in one invocation.
