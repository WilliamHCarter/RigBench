# v0.2 — multi-turn builder replay + prefix layout

**Goal.** Measure append-only context growth and establish cold versus
warm/prefix behaviour.

## The slice and its exact contract

A four-turn deterministic *replay* of a bounded builder loop, sent to each engine
config, with per-turn timing and cache fields, under two prompt layouts. Only the
final turn is scored. There is no live tool execution here — that is v0.4 — and
no reviewer fan-out, no context matrix, no engine tuning.

## Deliverables

| Deliverable | Where |
|---|---|
| 4-turn deterministic builder trajectory | `fixtures/zig-playback-v1/trajectories/builder-4turn.json` |
| Synthetic `TOOL_RESULT` / `TEST_RESULT` replay messages | same file; see *Provenance* below |
| Current-layout and cache-friendly-layout wrappers | `configs/layouts/` |
| Per-turn TTFT/wall/token/cache fields | `metrics.Record`; `stable_prefix_bytes`, `appended_bytes`, `turn_count`, `scored` added |
| Resident-server warm protocol | `run -warmup N`, per-turn thermal classes, `run.json`'s `warmup_policy` |

## Acceptance gate

Run with `agentbench smoke -slice v0.2`.

| Criterion | Result |
|---|---|
| Turn N prompt is byte-identical to turn N−1's prefix plus appended data | Asserted for every turn of both layouts, and again in the runner before each request is sent |
| Repeated run produces identical prompt hashes | The whole trajectory is serialized twice from scratch and the 4 hashes compared |
| Report cold T0 and warm T1–T3 separately | Turn 0 of a cold run is recorded `cold`, turns 1–3 `warm-resident`; the reporter keys cells on thermal class so they cannot merge |
| Prefix-friendly layout can be A/B tested without changing task semantics | `prompt.SameContent` requires the two layouts to carry an identical multiset of block digests at every turn |

## The trajectory

Four turns: implement → compile error → behavioural failure → frozen-golden
failure → repair. The scored turn is the last.

| Turn | Objective | Replayed result |
|---|---|---|
| 0 | Implement the seam | Compile error: `Cursor.taps` still takes `lo, hi` |
| 1 | Move the cursor to `FrameRange` | 5 test failures: reverse advance accepts a step below `range.start` |
| 2 | Fix the legality check | Player golden moved: the default path is no longer byte-identical |
| 3 | Repair the default path; return the complete diff | — |

### Provenance of the replayed output

Every `TEST_RESULT` is **real output from `zig build test --summary all`** run
against a real intermediate tree, not invented text:

| Turn | Tree it was captured from |
|---|---|
| 0 | Reference solution with `cursor.zig` reverted to HEAD |
| 1 | Mutant `m05-reverse-below-start` |
| 2 | Mutant `m07-default-path-moves-player-bytes` |
| 3 | The reference solution |

Absolute paths, toolchain paths, runtime addresses, RSS figures and durations are
replaced by stable placeholders. A frozen fixture may hold no bytes that would
differ on another machine: one absolute path in a replayed tool result moves the
prompt hash per host and destroys prefix reuse — which would then look like an
engine problem. A test asserts the shipped trajectory contains no host paths.

### Why the replay is canned rather than live

The assistant messages and tool results are fixture bytes and are appended
*regardless of what the model under test actually said*. That is not a shortcut.
It is the only way turn N's prompt can be a byte-exact prefix of turn N+1's,
which is the property that makes prefix-reuse telemetry interpretable at all. A
loop that fed back the model's own output would produce a different prompt for
every engine and every run, and no two rows would be comparable. v0.4 replaces
the replay with a live edit/test loop, and that is a different lane with a
different determinism story.

## What the layout A/B actually shows

This is the finding, and it is narrower than the obvious claim.

**Within one story, both layouts append cleanly.** A volatile-first layout's
leading objective does not change between turns of the same task, so turn-to-turn
reuse is *not* where the layouts differ. Measured, not assumed: both layouts pass
the append-only assertion at every turn, and a unit test pins it
(`TestCurrentLayoutStillAppendsWithinAStory`).

**Across tasks, they differ enormously.** A second story reuses a cache-friendly
layout's whole stable head and reuses essentially nothing of a volatile-first one:

| Layout | Reusable prefix | Share of final prompt | Cross-task reuse |
|---|---|---|---|
| `builder-cache-friendly` | 27,191 B | 69% | 27,136 of 27,645 B (98%) |
| `builder-current` | 1,552 B | 4% | 1,536 of 27,640 B (6%) |

`builder-current`'s 1,552 reusable bytes are exactly its system message: the only
stable block that precedes the volatile objective.

Cross-task reuse is computed at 256-byte block granularity, because a real KV
cache reuses whole blocks — a single differing byte near the head invalidates the
block containing it, so a one-character change cannot report a 99% hit.

## Cold and warm

Warm is produced deliberately and recorded; it is never inferred from elapsed
time.

- Turn 0 of a `-thermal cold` run is recorded `cold`. Turns 1..N are
  `warm-resident`, because the server is resident by then. A run declared
  `steady` is steady throughout.
- `-warmup N` sends N discarded priming requests before the first measured turn.
  They are not recorded as rows, but that they happened is recorded in
  `run.json`'s `warmup_policy`.
- `-warmup` on a `-thermal cold` run is refused: a cold run cannot be preceded by
  priming requests.
- The reporter keys cells on thermal class, so cold and warm rows are structurally
  unable to average together.

Sample multi-turn run against the mock, `builder-cache-friendly`, cold start:

| Config | Thermal | n | Wall ms | Visible TTFT ms | Prefix hit tok |
|---|---|---|---|---|---|
| `mock-ar` | cold | 1 | 6,402 | 338 | not exposed |
| `mock-dflash2` | cold | 1 | 2,310 | 336 | 0 |
| `mock-ar` | warm-resident | 3 | 6,132 (6,082..6,311) | 57 (47..58) | not exposed |
| `mock-dflash2` | warm-resident | 3 | 2,006 (2,000..2,010) | 55 (45..56) | 7,664 (6,837..8,683) |

**These are not measurements.** The endpoint is the in-repo mock and its prefix
cache is a *simulation*. What the numbers demonstrate is that the pipeline
separates cold from warm, that TTFT drops when a prefix is resident while decode
time does not, and that a generic telemetry adapter reports `not exposed` where a
vendor adapter reports a number.

## Bugs found and fixed while building this slice

1. **The `cold` label was a lie.** Both engine configs share one mock process, so
   the second engine's "cold" turn 0 hit a cache the first engine had already
   warmed — it reported 6,841 hit tokens and a 5 ms TTFT. Fixed with a
   `preEngine` hook the caller supplies, because only the caller knows how to
   produce a cold start for its endpoint. Cold turn 0 now reports 0 hit tokens.
2. **The CSV header and row drifted apart.** A 29-column header was emitted
   against a positional `Fprintf` with 28 verbs. Rewritten as name/value pairs so
   they cannot disagree, with a test asserting every row is as wide as
   `Columns()`.
3. **`StablePrefixBytes` was being filled with `PromptBytes`.** The prefix column
   silently reported the whole prompt, which would have made every layout look
   perfectly cacheable.
4. **Unscored replay turns were counted as failures.** A fully green four-turn run
   would have reported one pass and three failures.
5. **I first assumed the layout A/B would show a turn-to-turn win.** It does not,
   and the first version of this document would have claimed it did. The measured
   difference is cross-task, and the report now says so in the table's own
   caption.

## Unmeasured, stated rather than covered

- **The prefix cache is simulated.** The mock's cache reports the longest common
  block-aligned prefix with a previously-seen prompt. It models what a served
  cache *could* reuse; it is not a measurement of one, and no engine's real
  cache behaviour has been observed from this workstation.
- **No real inference has been run**, in this slice or the last.
- **The cross-task probe uses two objectives over one story.** Reuse across two
  genuinely different stories, with different source context, is not measured;
  it would be larger for neither layout and smaller for both.
- **Turn-level scoring is only at the final turn.** Whether an intermediate turn's
  output was a sensible repair is not judged, because the replay discards it.
- **Cache hit tokens are converted from bytes** by the mock at the same crude
  ratio it uses for prompt tokens. Hit plus miss equals the reported prompt count
  by construction; neither is a tokenizer result.
- Everything still unmeasured from [v0.1](v0.1.md) remains unmeasured: heuristic
  token counts, provisional Hipfire telemetry keys, and the structural control's
  single-loop scope.
