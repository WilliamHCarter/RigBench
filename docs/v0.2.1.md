# v0.2.1 — review fixes: making engine identity executable

A peer review of v0.1–v0.2 found two P0 integration bugs and two smaller issues,
all correct. This slice fixes them. It adds no benchmark capability; it makes two
claims the benchmark was already making become true.

Both P0s share a shape worth naming: **the benchmark was describing engine state
it had no mechanism to produce.** The rest of the design treats the benchmark as
something that can be wrong — tripwires, mutants, three-valued gates — and this
was a place where a config file was trusted without evidence.

## P0-1 — engine configs did not switch anything

`ar.json` said `speculation_mode: "off"` and `dflash2.json` said `"dflash2"`, but
the request path sends model, messages, sampling and tools. Speculation is a
process-level Hipfire setting; no OpenAI-compatible request can select it. So:

```
agentbench run -engines ar.json,dflash2.json -endpoint http://rig:11435/v1
```

produced two differently *labelled* rows from whatever single mode the daemon
happened to be in. Worse than no result, because it looks like one.

### Fix

**A preparation hook.** `-before-engine <script>` invokes `<script> <engine-name>`
once per engine, before anything is measured. The script owns all server
lifecycle — stop, reconfigure, load the drafter, restart, wait for readiness. Its
stdout and stderr land in `artifacts/engine-prep/<engine>.prepare.log`, and a
non-zero exit aborts the run.

It runs once per engine rather than once per repetition: a hook that restarts a
server would otherwise turn every steady-state repeat back into a cold one.

`scripts/prepare-hipfire.sh` implements the arms the review sketched, with a real
readiness gate that polls `/health` for `.model` resident and `.loading_model`
absent rather than sleeping. **Its Hipfire invocations are unverified from this
workstation** and the script says so at the top.

**An identity probe.** An engine config may declare:

```json
"identity_probe": {
  "path": "/health",
  "require": { "model": "qwen3.8:27b-fast" },
  "record": { "version": "engine_commit", "model_hash": "model_hash", "draft_model": "draft_hash" }
}
```

The response is stored as `artifacts/engine-prep/<engine>.probe.json`. A `require`
mismatch **aborts the run** — there is no warn-and-continue, because the entire
point is to stop a mislabelled row from being recorded. `record` pulls
reproducibility fields out of the server, so they stop depending on someone
remembering to paste a hash into a config.

**Attestation, recorded either way.** `run.json` now carries `attested` and
`attestation_method` per engine. A run with neither hook nor probe is not
refused — the mock lane legitimately has neither — but every such row is marked
**asserted** rather than attested, and when more than one engine is compared the
summary leads with a caveat saying the labels may all describe one configuration.

## P0-2 — `"thinking": "off"` did not turn thinking off

The client implemented `"off"` by not sending `reasoning_effort`. Omission is not
disabling. On a server whose default is to reason, the config said no-think and
the model reasoned anyway — contaminating wall time, TTFT, token counts, and
`DecodeTokSDerived` in particular, since that divides completion tokens by the
streaming window.

### Fix

`thinking_off_mechanism` is now **required** whenever `thinking` is `"off"`, with
three declared values:

| Mechanism | Wire form |
|---|---|
| `chat_template_kwargs` | `chat_template_kwargs: {"enable_thinking": false}` |
| `reasoning_effort_none` | `reasoning_effort: "none"` |
| `omit` | nothing — correct only where the endpoint's default is genuinely non-reasoning, and now a deliberate statement |

A config that says `"off"` with no mechanism fails at load with an error
explaining why omission is not disabling. Both rig configs use
`chat_template_kwargs`.

The exact request bytes are now kept as `artifacts/.../request.json`, so "this
run was no-think" is checkable after the fact rather than inferred from a config.

### And the check is not vacuous

`smoke` gained a **no-think gate with a negative control**, because a mock that
never reasoned would pass a zero-reasoning-tokens assertion forever:

```
== no-think is actually requested ==
  mock-ar                    0 reasoning tokens, and the sent body carries enable_thinking=false
  mock-dflash2               0 reasoning tokens, and the sent body carries enable_thinking=false
  mock-nothink-omit-control  63 reasoning tokens — the check above is not vacuous
```

The mock now emits reasoning unless a request actually disables it, and
`configs/engines/controls/mock-nothink-omit-control.json` is a deliberately wrong
config kept solely as that control. It is labelled, in its own description, as
never usable for a measurement.

## P1-1 — asymmetric telemetry adapters

AR used `generic` while DFlash used `hipfire`, so the AR row silently lost
prefill, decode and cache fields. Both rig configs and both mock configs now use
`hipfire`. The adapter is defensive by construction: every field stays `null`
unless observed, and a wrong guess at a key name yields `null` rather than a
number. Unit tests now pin that a reported zero and an absent field never
collapse into each other.

## P1-2 — repro identity was mostly nullable

`identity_probe.record` populates `engine_commit`, `model_hash` and `draft_hash`
from the server. Separately, the summary's new **Engine identity** table names
every config recording no engine commit or model hash and says plainly that a
champion selected on those rows could not be reproduced.

## Naming: mechanism versus drafter

`speculation_mode` is now `"dflash"` — Hipfire's actual mechanism — with the
drafter architecture moved to `non_default_knobs.draft_arch: "DFlash2"`. Keeping
them separate is what makes a later F16/MQ6/MQ4 drafter sweep nameable. A test
pins the distinction.

New tests that would have caught the original P0s:

- `TestThinkingOffSendsARealSwitch` — the sent body must carry the switch
- `TestThinkingOffWithNoMechanismIsRefused` — no silent degradation to "send nothing"
- `TestThinkingOffRequiresAMechanism` — config-level, with the explanatory error
- `TestShippedRigConfigsAreAttestable` — the rig configs must declare an identity probe, use the same adapter on both sides, and not claim no-think by omission
- `TestSpeculationModeNamesTheMechanismNotTheDrafter`
- `TestGenericAdapterExtractsNothing`, `TestHipfireAdapterKeepsZeroDistinctFromAbsent`

## Still unmeasured

- **The Hipfire CLI calls, config keys and `/health` schema are unverified.** Step 0
  of [the runbook](rig-campaign.md) exists to correct them before a campaign.
- **`identity_probe.require` currently only pins the model name.** If your build
  exposes a field that distinguishes AR from DFlash, adding it there is what turns
  attestation from "we ran a script" into "we checked".
- **No real inference has been run**, still.
- **HTTP keep-alives remain disabled**, deliberately, to keep `http_connected_ms`
  meaningful. A persistent agent process would reuse connections; revisit once
  inference itself is fast enough for connection setup to matter.
- Everything unmeasured in [v0.1](v0.1.md) and [v0.2](v0.2.md) remains so.
